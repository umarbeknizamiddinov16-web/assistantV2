# SmartAI Assistent: AI-ассистент для анализа вакансий и сопроводительных писем

Telegram-бот (aiogram 3) + веб-сайт + FastAPI + MongoDB Atlas (motor) + OpenRouter + hh.ru API.

Один и тот же сервис работает и как Telegram-бот, и как сайт: после запуска откройте `http://localhost:8000/`.

## Как это работает
1. `📄 Резюме`: текст или файл `.pdf` / `.docx` / `.txt` (`ResumeParser`, извлечение в отдельном потоке).
2. `⚙️ Фильтры`: FSM из 3 шагов (должности → город → тип занятости), по умолчанию Ташкент.
3. `🔍 Поиск вакансий` (порядок строгий, этапы видны в статусе поиска):
   1. **ИИ читает резюме** (`AIService.profile_resume`): уровень, роли, навыки, поисковые запросы. Профиль кэшируется в `users`
      на версию резюме (по хэшу), при смене или удалении резюме читается заново.
   2. `HHScraper` ищет вакансии на hh.ru по вашим должностям из фильтров (User-Agent строго из `HH_USER_AGENT`);
      вакансии, чей ID уже есть в коллекции `vacancies`, повторно не загружаются.
   3. **Отбор по резюме** (`AIService.screen_vacancies`): одним запросом ИИ оценивает всю выдачу с учётом профиля.
      Вакансии с оценкой ниже `MIN_MATCH_SCORE` (по умолчанию 40) отсеиваются, лучшие идут первыми.
   4. `AnalysisService` делает подробный разбор (Match Score, недостающие навыки, письмо) только для лучших
      (`MAX_VACANCIES_PER_SEARCH`) и только для пар, которых ещё нет в `analysis_logs`. Если и подробный разбор даёт оценку ниже порога,
      вакансия не показывается. Карточки приходят по мере готовности.
   Если ИИ не смог прочитать резюме или оценить выдачу, поиск не падает: порядок hh.ru сохраняется, отбор по оценкам пропускается.
   Если подходящих нет, показывается сообщение об этом и демонстрационные примеры.
4. Кнопка `📄 Сгенерировать сопроводительное письмо`: письмо берётся из `analysis_logs` мгновенно (ИИ не вызывается),
   выводится моноширинным блоком для копирования в один тап.

ИИ возвращает один JSON: `{"match_score": int, "missing_skills": [..], "cover_letter": "..."}`. Ответ валидируется,
при невалидном JSON делается повторный запрос, при недоступности модели используется `OPENROUTER_FALLBACK_MODEL`.

## Чат с ИИ (только о работе)
`💬 Чат с ИИ` в боте (режим чата, выход «⬅️ Выйти из чата» или `/cancel`) и кнопка «Чат с ИИ» на сайте. Нужны резюме и вход в аккаунт.
- Общий ключ и модель: тот же `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` и запасная `OPENROUTER_FALLBACK_MODEL`, что и для поиска.
- Сначала ИИ читает резюме (профиль), потом отвечает с его учётом. История чата общая для сайта и бота (коллекция `chat_messages`).
- Пользователь может писать, например, «какие работы с большой зарплатой мне подойдут». ИИ возвращает ответ и термины для поиска,
  сервис ищет вакансии на hh.ru по этим терминам (режим «высокая зарплата»: только с указанной зарплатой, сначала самые высокие),
  сверяет их с резюме и показывает только подходящие (до 5 карточек: компания, зарплата, совпадение с резюме, ссылка).
  Если hh.ru недоступен, показываются подходящие по терминам демонстрационные примеры с пометкой.
- **Строго по теме.** Допустимо: вакансии, профессии, зарплаты, навыки и обучение для карьеры, резюме, письма, собеседования.
  Защита в несколько слоёв: правила в системном промпте; модель только классифицирует вопрос (`on_topic`), а для вопроса не по теме
  отвечает фиксированный текст сервиса (`OFF_TOPIC_REPLY`), текст модели игнорируется; вопрос не по теме не попадает в историю и в контекст;
  резюме, вакансии и сообщения передаются как данные, а не инструкции; ограничения: 500 символов в сообщении, 20 сообщений за 10 минут.
  Ограничение вероятностное: определяет тему модель, поэтому на очень хитрые формулировки нужно проверять на выбранной модели.
- API: `GET|POST|DELETE /api/chat`.

## Веб-интерфейс
Сайт открывается на `/` и использует те же сервисы, что и бот (резюме, фильтры, анализ, письма).
- **Регистрация и вход:** логин + пароль + email (имя необязательно, по умолчанию это логин). Вход: логин + пароль + email (все три поля должны относиться к одному аккаунту).
  Хэш пароля scrypt, пароль нигде не хранится в открытом виде, сессия 30 дней в httpOnly-cookie.
  Имя подставляется в подпись сопроводительного письма вместо `[Ваше имя]`.
- **Первый запуск:** после регистрации пошаговый мастер: резюме → должности, город, тип занятости → поиск стартует сразу.
  Позже всё редактируется на главной странице.
- Для веб-аккаунта хранится одно резюме: после сохранения загрузка скрывается, а новое можно добавить только после подтверждённого удаления текущего.
- Нажатие на карточку вакансии открывает подробности (описание, требования, условия, ссылка на первоисточник) без перезагрузки страницы.
  Если hh.ru не отдаёт полное описание, показываются данные, сохранённые при поиске. Если поиск ничего не дал или hh.ru недоступен,
  под кнопкой поиска показываются оригинальные демонстрационные примеры с явной пометкой (это не реальные вакансии, откликнуться на них нельзя).
- Сайт сам подтягивает изменения, сделанные в боте (при возврате на вкладку и раз в 20 секунд), не затирая то, что пользователь сейчас вводит.
- Аккаунты лежат в коллекции `web_accounts`, сессии в `web_sessions` (TTL-индекс). Данные поиска хранятся в тех же `users` / `vacancies` / `analysis_logs`
  под `user_key` аккаунта. Аккаунт общий с Telegram-ботом (см. ниже).
- Результаты поиска приходят потоком (Server-Sent Events, `GET /api/search` (поток событий `stage`, `plan`, `card`, `failed`, `done`)): карточки появляются по мере готовности.
- API: `POST /api/auth/register` (`login`, `email`, `password`, необязательно `name`), `POST /api/auth/login` (`login`, `email`, `password`), `POST /api/auth/logout`, `GET /api/me`, `PUT|DELETE /api/resume`, `POST /api/resume/file?filename=`, `PUT /api/filters`, `GET /api/search` (поток событий `stage`, `plan`, `card`, `failed`, `done`), `GET /api/vacancies/demo`, `GET /api/resume`, `GET /api/vacancy/{id}`, `GET /api/letter/{id}`.
- Ограничения (в памяти процесса): `WEB_SEARCHES_PER_HOUR` поисков в час на аккаунт (по умолчанию 10, `0` отключает), 12 попыток входа за 15 минут с одного IP.
  За прокси передавайте `X-Forwarded-For` / `X-Forwarded-Proto`. При нескольких экземплярах приложения лимиты считаются отдельно в каждом.
- Отключить сайт и оставить только бота: `WEB_ENABLED=false`.

## Аккаунт: один на бота и сайт
Бот сразу просит создать аккаунт или войти (кнопки «📝 Создать аккаунт» / «🔑 Войти», команды `/register`, `/login`, `/logout`).
Без входа остальные функции бота недоступны.
- **Создание в боте:** логин → пароль → email → имя (можно пропустить). Сообщение с паролем бот сразу удаляет из чата,
  в памяти FSM остаётся только хэш. Тем же логином, паролем и email можно войти на сайте.
- **Вход в боте:** логин, email и пароль (пароль последним, его сообщение тоже удаляется). Так подключается и аккаунт, созданный на сайте.
- **Что синхронизируется:** резюме, фильтры, результаты анализа и письма: всё хранится под `user_key` аккаунта,
  изменения на сайте сразу видны в боте и наоборот. Поиск идёт под тем же ключом, поэтому одновременный поиск с сайта и из бота не запускается
  (второй получит «Предыдущий поиск ещё выполняется»).
- **Старые данные присоединяются:** если человек работал с ботом до появления аккаунтов, при входе в аккаунт, созданном на сайте,
  его резюме, фильтры и результаты анализа переносятся в аккаунт. Данные аккаунта не перезаписываются: резюме переносится только если
  у аккаунта его ещё нет (иначе бот сообщит, что своё резюме в аккаунте уже есть), фильтры только если у аккаунта нет должностей.
  Данные, принадлежащие другому аккаунту, не переносятся никогда. Перенос идёт один раз, старая запись после него удаляется.
- Один аккаунт привязывается к одному Telegram (поле `telegram_id`). «🚪 Выйти» / `/logout` отвязывает Telegram,
  аккаунт и данные остаются. Попытки входа в боте ограничены: 8 за 15 минут на пользователя, регистраций 5 в час.
- Если аккаунт создаётся прямо в боте, прежние данные пользователя сохраняются как есть (`user_key` = его Telegram id).
- Аккаунты, созданные на сайте до появления логинов, продолжают работать: при первом входе введите email, пароль и желаемый логин,
  он закрепится за аккаунтом (если свободен).
- При первом запуске после обновления создаются индексы `web_accounts`: уникальные `user_key`, `login` и `telegram_id`
  (последние два только для заполненных значений, поэтому старые аккаунты без логина продолжают работать, входя по email).

## Структура
```
app/
  main.py                    FastAPI: lifespan, /health, /webhook, запуск бота
  config.py                  настройки из .env
  container.py               DI-контейнер (ai, scraper, resume_parser, analysis, chat)
  db.py, repositories.py     MongoDB: users / vacancies / analysis_logs / chat_messages
  utils.py                   HTML-очистка, извлечение JSON, разбиение сообщений
  bot/                       handlers.py, auth.py (аккаунты и доступ), keyboards.py, states.py
  web/                       api.py (веб-API), accounts.py (общие аккаунты, сессии), static/ (index.html, style.css, app.js)
  services/
    resume_parser.py         ResumeParser
    scraper.py               HHScraper
    ai_service.py            AIService (OpenRouter)
    analysis_service.py      AnalysisService (оркестрация поиска: резюме → hh.ru → отбор → разбор)
    chat_service.py          ChatService (чат строго о работе, подбор вакансий по терминам)
tests/                       pytest
```

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env        # заполните ключи
uvicorn app.main:app
```
Docker: `docker compose up --build -d`. Webhook: задайте `WEBHOOK_BASE_URL` и `WEBHOOK_SECRET`.

## Тесты
```bash
pip install -r requirements-dev.txt && pytest
```

## Важно
- Бесплатные модели OpenRouter меняются. Текущие модели по умолчанию: `google/gemma-4-31b-it:free`
  и резервная `google/gemma-4-26b-a4b-it:free`; при необходимости замените их в `.env`
  на модели из актуального списка на openrouter.ai/models.
- Параметры фильтров hh.ru (`HH_EMPLOYMENT` в `scraper.py`) могут меняться: при ошибке 400/403 от hh.ru проверьте их и `HH_USER_AGENT`.
- Из выдачи hh.ru берётся первая страница (`HH_CANDIDATES`); если все вакансии уже проанализированы, бот показывает прежние карточки без затрат на ИИ.
- На один поиск уходит один запрос на «чтение» резюме (только при новой версии резюме), один запрос отбора и по запросу на подробный разбор лучших вакансий; в чате один запрос на сообщение (плюс отбор, если ищутся вакансии). На бесплатных моделях OpenRouter лимиты быстро заканчиваются, поэтому `AI_CONCURRENCY` и `MAX_VACANCIES_PER_SEARCH` лучше не завышать.
- FSM хранится в памяти: при перезапуске незавершённый ввод сбрасывается.
